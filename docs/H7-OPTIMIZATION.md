## 1. 容器正视图可视化 + 临期位置徽章

### 1.1 现状与问题
容器详情页当前是 `rows × columns` 张**独立小卡片**平铺，是工程师视角不是店长视角；
临期商品的位置码只是列表里的一行小字，扫一眼看不出在哪个格。

### 1.2 改造方案（纯视图层，数据层不动）

- **画成一个整体柜体**：外框按容器类型分视觉
  - `Fridge` 冰柜：冷色（钢灰蓝）面板 + 门缝线 + 顶部把手条
  - `Shelf` 货架：暖色（木纹米黄）层板，每层一条横向层板阴影
- **格子按真实尺寸排**：行数 = `container.rows`，列数 = `container.columns`，格子宽高比跟随，2×3 就真的长成两行三列
- **格内商品从前往后叠放**：沿用现有 mini 色块渲染，空位画虚线占位，格底标占用数 `2/5`
- **点格位 → `CellSheet`**：现有链路，不动（上架到此格 / 明细 / 下架入口都在里面）
- 高亮逻辑保留：从首页提醒跳转进来时，对应格位描边加粗 + 轻微放大

### 1.3 临期位置徽章（与 1.2 同一轮）

统一一个 `LocationBadge` 组件，等宽字体 + 胶囊底：

| 状态 | 样式 |
|---|---|
| 正常 | 灰底深字 `A1` |
| 临期 | **黄底黑字** `B2` |
| 过期 | **红底白字** `B3` |

落地三处：
1. **首页今日临期/过期提醒列表** —— 徽章放行首，字号比现在大两号、加粗，比商品名更靠前
2. **容器正视图格内** —— 临期/过期商品的色块右上叠一枚 `B2` 角标
3. **下架列表** —— 同上，方便现场指认

> 原则：**位置码是全局统一的视觉锚点**。店长只要记住「黄底 B2」，在首页、货架、下架页看到的永远是同一个东西。

### 1.4 影响
`ContainerViews.swift` 已 397 行贴上限 → 需要新增文件承载新视图（见 §9）。

### 1.5 第一次尝试失败记录（2026-10-24 17:00 回滚）

**症状：** 装到真机后点格子打不开「上架到此格」流程。
**回滚：** commit `b2fe790`，回到 H6 已验收状态（`CellBox` 网格 + `.onTapGesture`）。

**最可能的原因（重做时必须先修）：**
1. **装饰层吃掉点击** —— 冰柜的玻璃反光 `Rectangle` 与门把手 `Capsule` 是画在货位**之上**的普通视图，SwiftUI 会给它们分配点击区域。反光条宽度 46pt、高度撑满内胆，正好压住中间几列。**所有纯装饰视图必须加 `.allowsHitTesting(false)`**。
2. 重做时不要用 `Button` 包货位，沿用原来验证过的 `.onTapGesture`，减少变量。

**重做流程：** 模拟器里先用临时调试页截图确认外观 → **再手动点一次格子验证能开格位面板和上架** → 才装真机。

## 2. 右上角 `+` → 编辑货架规格

### 2.1 语义变更
| 位置 | 变更前 | 变更后 |
|---|---|---|
| 容器详情右上角 `+` | 上架商品（自动挑格） | **编辑本货架规格** |
| 点具体格子 → 格位面板 | 已有「上架到 X 格」 | 不变，**上架唯一入口** |

理由（Steven）：柜子的物理规格会变，但上架行为必须绑定到人实际站到的那一格。

### 2.2 编辑表单
预填当前值，可改：名称 / 行数 / 列数 / 每格纵深容量。保存即 `save()`，首首页与容器列表自动重算。

### 2.3 缩小校验（数据安全规矩）

| 情况 | 行为 |
|---|---|
| 尺寸改大 | 直接放行 |
| 缩小后所有商品仍装得下 | 放行 |
| 缩小导致商品悬空（格位不存在 / 纵深超新容量） | **拒绝保存**，红字列出冲突：「C 格还有 2 件，无法将纵深改为 3，请先移出」 |

**不做自动搬家。** 商品位置是物理事实，App 替店长决定「搬到哪一格」反而吓人，报错让他自己清更直觉。
对应不变量：`docs/DATABASE.md` §3 I2（格内从 1 连续排、无空洞）。

### 2.4 实装（2026-10-24 17:12）

- 数据层：`Models.swift` 新增 `ResizeConflict` + `resizeConflicts(in:rows:columns:depthCapacity:)`，纯函数、可单独验证（自检输出见下）
- 视图层：新文件 **`ContainerFormView.swift`（⑦ 号槽位）** —— `ContainerFormSheet(mode: .create / .edit(container))` 一个表单复用两种模式；
  原 `CreateContainerSheet` 从 `ContainerViews.swift` 删除（该文件 397 → 329 行）
- 右上角 `+` 图标由 `plus` 改为 `slider.horizontal.3`，避免与「新建容器」的 `+` 混淆
- 缩容冲突在表单内**实时显示**并禁用「保存」按钮 —— 用户不需要先点保存才知道不行

自检（真实 SwiftData，牛奶冰柜 3×2×5、在库 A1 / B1 B2 / C1）：

| 改成 | 结果 |
|---|---|
| 3×2×5（不变）、4×2×5、3×2×10（变大） | ✅ 允许 |
| 2×2×5（6 格 → 4 格，C 仍在） | ✅ 允许 |
| 1×2×5 | ❌ 「C 格还有 1 件，新规格没有这一格」 |
| 3×2×1 | ❌ 「B 格有 2 件，超过新的纵深 1（超出 1 件）」 |
| 1×1×1 | ❌ 两条冲突同时列出 |

合法缩小落库后 `nextSlot` 仍给出 A2、上架成功 —— 不变量未被破坏。

## 3. 登录页（假登录，不需要真账号）

- 全屏 `LoginView` 盖在 `TabView` 之上，未登录不进主界面
- 手机号：`TextField` + 数字键盘，**11 位中国手机号正则校验**
- 密码：`SecureField`，**≥6 位**
- 校验不过 → 红字提示，不弹系统弹窗
- 登录成功 → `@AppStorage("hasLoggedIn")` 置 true → 进主界面；**杀 App 重开不再要求登录**（这才像真的）
- 设置页加一行「退出登录」，点它回到登录页（演示时可反复展示登录流程）
- **预留位置**：语言切换开关（§7）、「店主 / 顾客」角色占位（§6 若做）

> 不存储任何账号数据。这是纯 UI 演示，对外讲解时如实说明「账号体系为 Deferred」。

## 6. 临期专区（降级版贩卖窗口）

### 6.1 为什么降级
完整「临期宝交易平台」= 双角色账号 + `Listing` / `Order` 模型 + 店主接单 + 客户下单 + 多店 seed，3–4h 起步，且把产品故事从「库存管理工具」拉成「交易平台」，评委提问面翻倍。

### 6.2 本轮做
- 店主从**临期/过期列表**一键「挂牌出售」→ 填折扣价与数量 → 生成一条 `Listing`
- 新增一个「临期专区」页：美团式商品卡（商品名 / 原价 / 折后价 / 折扣标 / 取货位置 / 剩余件数）
- 卡片页可投屏、可截图分享

### 6.3 本轮不做（对外如实说）
客户账号、下单/支付流程、跨店浏览、库存自动扣减、订单状态机。
讲解话术：「这是临期商品流通的入口，往交易平台长是下一步。」

## 7. 中英文切换（方案 B，高频页）

### 7.1 选 B 的理由
A（跟随系统语言）在演示机是中文系统时根本看不到英文，等于白做。
B（App 内切换）符合「可以选择语言」的原始需求，登录页放一个中/英切换，现场当场切给评委看。

### 7.2 实现方式
轻量 `L("key")` 助手 + 双语字典，不引入 String Catalog（避免为了 40 个串动全套本地化管线）。
语言选择存 `@AppStorage`，改完当前界面立即重绘。

### 7.3 范围（约 40 个字符串）
| 页面 | 覆盖 |
|---|---|
| 登录页 | 全量（这是展示切换的地方） |
| Tab 栏 | 全量（首页 / 容器 / 下架 / 设置） |
| 首页四卡 + 提醒列表 | 全量 |
| 容器列表 / 详情 / 格位面板 | 全量 |
| 上架表单 | 全量 |
| 设置页 | 全量 |
| 扫码提示 / 错误 toast / 空态文案 | **保留中文**（低频，现场切英文翻不到） |
