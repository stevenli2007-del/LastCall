## 1. 容器正视图可视化 + 临期位置徽章

### 1.1 现状与问题
容器详情页当前是 `rows × columns` 张**独立小卡片**平铺，是工程师视角不是店长视角；
临期商品的位置码只是列表里的一行小字，扫一眼看不出在哪个格。

### 1.2 改造方案（纯视图层，数据层不动）

- **画成一个整体柜体**：外框按容器类型分视觉
  - `Fridge` 冰柜：冷色（钢灰蓝）面板 + 门缝线 + 顶部把手条
  - `Shelf` 货架：暖色（木纹米黄）层板，每层一条横向层板阴影
- **格子按真实尺寸排**：行数 = `container.rows`，列数 = `container.columns`，格子宽高比跟随，2×3 就真的长成两行三列
- **格内商品从前往后叠放**：沿用现有 mini 色块渲染，空位画虚线占位，格底标占用数 `2/5`
- **点格位 → `CellSheet`**：现有链路，不动（上架到此格 / 明细 / 下架入口都在里面）
- 高亮逻辑保留：从首页提醒跳转进来时，对应格位描边加粗 + 轻微放大

### 1.3 临期位置徽章（与 1.2 同一轮）

统一一个 `LocationBadge` 组件，等宽字体 + 胶囊底：

| 状态 | 样式 |
|---|---|
| 正常 | 灰底深字 `A1` |
| 临期 | **黄底黑字** `B2` |
| 过期 | **红底白字** `B3` |

落地三处：
1. **首页今日临期/过期提醒列表** —— 徽章放行首，字号比现在大两号、加粗，比商品名更靠前
2. **容器正视图格内** —— 临期/过期商品的色块右上叠一枚 `B2` 角标
3. **下架列表** —— 同上，方便现场指认

> 原则：**位置码是全局统一的视觉锚点**。店长只要记住「黄底 B2」，在首页、货架、下架页看到的永远是同一个东西。

### 1.4 影响
`ContainerViews.swift` 已 397 行贴上限 → 需要新增文件承载新视图（见 §9）。

### 1.5 第一次尝试失败记录（2026-10-24 17:00 回滚）

**症状：** 装到真机后点格子打不开「上架到此格」流程。
**回滚：** commit `b2fe790`，回到 H6 已验收状态（`CellBox` 网格 + `.onTapGesture`）。

**最可能的原因（重做时必须先修）：**
1. **装饰层吃掉点击** —— 冰柜的玻璃反光 `Rectangle` 与门把手 `Capsule` 是画在货位**之上**的普通视图，SwiftUI 会给它们分配点击区域。反光条宽度 46pt、高度撑满内胆，正好压住中间几列。**所有纯装饰视图必须加 `.allowsHitTesting(false)`**。
2. 重做时不要用 `Button` 包货位，沿用原来验证过的 `.onTapGesture`，减少变量。

**重做流程：** 模拟器里先用临时调试页截图确认外观 → **再手动点一次格子验证能开格位面板和上架** → 才装真机。

## 2. 右上角 `+` → 编辑货架规格

### 2.1 语义变更
| 位置 | 变更前 | 变更后 |
|---|---|---|
| 容器详情右上角 `+` | 上架商品（自动挑格） | **编辑本货架规格** |
| 点具体格子 → 格位面板 | 已有「上架到 X 格」 | 不变，**上架唯一入口** |

理由（Steven）：柜子的物理规格会变，但上架行为必须绑定到人实际站到的那一格。

### 2.2 编辑表单
预填当前值，可改：名称 / 行数 / 列数 / 每格纵深容量。保存即 `save()`，首首页与容器列表自动重算。

### 2.3 缩小校验（数据安全规矩）

| 情况 | 行为 |
|---|---|
| 尺寸改大 | 直接放行 |
| 缩小后所有商品仍装得下 | 放行 |
| 缩小导致商品悬空（格位不存在 / 纵深超新容量） | **拒绝保存**，红字列出冲突：「C 格还有 2 件，无法将纵深改为 3，请先移出」 |

### 1.5 回滚与部分恢复（2026-10-24）

**回滚原因：** 装饰层（玻璃反光 Rectangle / 门把手 Capsule）画在货位**之上**且未加 `.allowsHitTesting(false)`，
把中间几列的 `.onTapGesture` 吃掉了 → 点格子无法上架。

**恢复（17:24，commit `95a3b4f`，Steven 指示「徽章和纵深不该一起回滚」）：**
- `LocationBadge`（含在 `ContainerViews.swift`，不占新文件）：等宽胶囊徽章，黄底 = 临期 / 红底 = 过期 / 灰底 = 正常，
  `regular / large` 两档字号
- 落地三处：**首页提醒行首**（`AlertRow`，下架列表复用同一组件）、**格内商品徽章**、**格位弹窗**
- 格内纵深表达：越靠后透明度越低（每层 −15%，最多 3 层）、向右偏移 2pt/层
- **有临期 / 过期货的格子整格描边**（黄 / 红）—— 扫一眼柜子就知道哪格要清；正常格不描边
- 验证：模拟器截图确认首页三枚徽章（红 B2 / 黄 C1 / 黄 B1）与格内效果；临时调试入口已删除（grep 0 残留）
- **柜体改造（冰柜 / 货架拟物）仍暂缓**，恢复时需申请第 10 个文件槽位并带 `.allowsHitTesting(false)` 规矩

**不做自动搬家。** 商品位置是物理事实，App 替店长决定「搬到哪一格」反而吓人，报错让他自己清更直觉。

## 8. 配货单识别（⏸ 已停放 · 2026-10-24 18:05）

> **状态：** 需求与技术方案已确认，Steven 决定**本轮不做**（先做中英文），代码未写。
> 下面把拍板的结论、踩点与设计细节固化下来，下一轮照此实现即可，不需要重新讨论。

### 8.1 需求（Steven 原话转化）

进货时店长手里有一张**配货单**（美宜佳热敏打印单据），每行含：序号 / 商品代码 / **商品条码** / **品名** / 单位 / 包装规格 / 数量 / **配货价** / 配货金额。希望：

1. 首页有个入口，**拍照或相册上传**配货单
2. App **自动识别**出「条码 + 品名 + 配货价」，确认后入库成条码字典
3. **上架时**：扫到/输入条码 → **autofill 商品名**（不用手打）
4. **挂牌时**：展示**配货价**作为定价参考（知道成本下限）

### 8.2 已拍板的三项决定（Steven 2026-10-24 18:02 选定）

| 决策点 | 结论 |
|---|---|
| 识别技术 | **A. 端侧 Vision OCR**（`VNRecognizeTextRequest`，accurate + `zh-Hans`）**离线**，不用 LLM |
| 字典存储 | **JSON 文件** `Documents/catalog.json`（Codable），**不建 SwiftData 模型** |
| 入口位置 | **首页第 5 张卡**（四张概览卡下方，全宽一行） |

**为什么不用 LLM 抓取：** ① 单子是机打热敏纸、列位固定，是 OCR 舒适区；② LastCall 铁律是「飞行模式可完整运行」（验收标准 12），配货恰恰发生在信号差的仓库；③ 演示话术更强 ——「端侧离线识别，数据不出设备」比「调了个 API」加分。
**为什么不用 SwiftData 模型：** 手机里已有数据，新建 `@Model` 要再赌一次 schema 迁移（H7-6 那次等了 6 秒确认没崩）。字典是辅助数据，JSON 零迁移风险且可导出。

> Steven 提的「AI 匹配」其实不需要 AI：条码是精确字符串，字典 `O(1)` 查询即可。**AI 只在抓取那一步有价值**，本轮按上面的决定不做。

### 8.3 实现设计（下一轮照此写）

**新文件 `CatalogViews.swift`（⑩ 槽位，需 ADR 批准文件数 9→10）**

```
⑩ CatalogViews.swift
   ├─ CatalogEntry / ProductCatalog  目录 JSON 读写（load/save/upsert/count）
   ├─ ParsedRow + ReceiptParser      纯函数解析，无 UI 依赖，可单独跑测试
   ├─ ReceiptOCR                     Vision 文本识别 → 按视觉行聚合 → 文本行数组
   ├─ CatalogHomeCard                首页第 5 张卡（ContentView 只加 1 行）
   └─ CatalogImportSheet             PhotosPicker + 拍照 → 处理中 → 可编辑确认页
```

**OCR → 解析流程**

1. `PhotosPicker` 选图（或 `UIImagePickerController` 拍照，模拟器不可用时隐藏拍照按钮）
2. `VNRecognizeTextRequest`：`recognitionLevel = .accurate`、`recognitionLanguages = ["zh-Hans"]`、`usesLanguageCorrection = false`（保护条码与价格数字）
3. **按视觉行聚合**：Vision 会把同一行的不同列拆成多个 observation，必须按 `boundingBox` 的**中线 Y 聚类**（阈值取行高中位数 × 0.6），行内按 **minX 从左到右**拼接 —— 直接逐条 observation 解析会丢一半
4. 每行用正则提取：
   - **条码**：`(?<!\d)\d{13}(?!\d)`，取该行第一个
   - **配货价**：该行所有 `\d+\.\d{1,2}`（小数只有价格列用），**倒数第 2 个 = 配货价**，最后 1 个 = 配货金额
   - **品名**：条码之后的串，切到第一个小数前；按空格切 token，遇到纯数字 / `\d+\*\d+` / 单位字符（袋瓶盒箱桶包罐杯支）/ 单个尺码字母（A–H）即停；去掉开头 `※`、`*`
   - 以条码去重（同一张单多次出现只留一条）
5. **识别不出来的行不丢弃** —— 确认页标黄并写明缺什么（「未识别到品名」「未识别到配货价」），让人手补。宁可见人改，不可看不见
